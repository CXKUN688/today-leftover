## 1. 目标与已确认范围

用户使用小米 15，自报安卓 17。制作可安装的安卓 APK，输入月生活费，根据实际月份天数和消费动态计算剩余每日额度；支持分类记账、微信与支付宝账单辅助记账。保留预留资金、退款与自己账户间转账区分。

第一版为个人本地账本，无需注册。界面为中文、人民币、浅色卡片、大号金额、底部导航。采用原生 Kotlin、Jetpack Compose 和 Room。手机型号与系统版本属于用户提供的信息，尚未连接设备核验。以 Android 17 为兼容验收目标；具体 compileSdk、targetSdk 与依赖版本在实施时根据官方发布和可用工具链锁定，不能将用户系统名称当作已经可用的 SDK 版本。

## 2. 页面与操作

- 首页：本月预算、剩余可用预算、今日已花、剩余每天可花、预算进度、待确认笔数，以及明显的记账入口。
- 记账：金额、支出/退款/收入/内部转账、分类、交易时间、用途备注、付款方式，可关联预留项或原消费。支持编辑、删除及重新计算。
- 明细与统计：月份切换，按分类与付款方式筛选，日流水、分类汇总和支出占比。统计明确区分支出、退款、收入、内部转账。
- 账单助手：通知识别开关和权限状态，待确认列表，文件导入预览、错误说明、重复提示与提交结果。
- 设置：月预算、预留资金、自定义分类、备份和恢复。默认分类为餐饮、交通、购物、娱乐、学习、住宿、医疗、其他。

首次使用依次填写本月生活费、可选预留项及此前已花金额。无需先授予通知权限；拒绝权限仍可手动记账与导入。

## 3. 预算计算与时间规则

金额统一以整数分保存，避免浮点误差；输入最多两位小数，拒绝空金额、负金额、零金额交易及溢出。交易金额本身为正，通过类型表达方向；月预算允许为零。

当前月可支配余额 = 月生活费 + 明确加入预算的额外收入 + 本月到账退款 - 本月消费支出 - 此前已花调整项 - 尚未使用的预留金额。

剩余每天可花 = 当前月可支配余额 / 本月剩余天数（含今天）。内部用精确整数金额计算，显示到分，采用向下取整，避免承诺超出余额。负余额明确显示超支金额，不隐藏为零；负的平均值标注为日均缺口。首页标注“剩余每天可花（含今天）”，不将它命名为固定不变的“今日限额”。每笔有效账目更新后重算。

按设备本地日期确定今天，交易保存发生时间与记账日期；已记账日期不会因之后切换时区被悄悄改写。应用进入前台及日期跨日时刷新。按日历计算 28、29、30、31 天。未来日期第一版不允许记为已发生交易。

历史月份展示结余和当月统计，不再显示当前意义的剩余每日额度。新月份可沿用上月预算及周期预留模板，必须按月份幂等生成，重复打开不重复创建。上月余额默认不结转；用户可显式将正结余加入新月预算。旧月记录与预算保留。

## 4. 预留资金与特殊交易

预留项包含名称、月份、目标金额及关联支出。未使用预留 = max(目标金额 - 关联净支出, 0)。例如预算 2,000 元、预留房租 500 元，可用 1,500 元；支付并关联 500 元房租后，支出增加 500 元、剩余预留减少 500 元，可用仍为 1,500 元。超过预留的支出消耗普通预算。删除或修改关联支出时同时重新计算。

退款可关联原消费，支持部分退款，关联累计退款不得超过原消费金额。退款以实际到账月份回补预算。若原消费及预留属于当前月，退款同时恢复该预留的未使用额度；跨月退款不重新激活已结束月份的预留。找不到原消费的退款允许人工确认后入账，明确标记未关联，不凭相同金额自动绑定。

只有本人账户之间的资金移动默认记为内部转账，不消耗生活费；“转账”字样本身不足以确定是内部转账。转给别人、红包、充值、信用卡还款等含义不明确的导入或通知必须待确认，避免漏算消费或重复扣款。收入默认不增加预算，可由用户明确选择“加入本月预算”，且只增加一次。

月中开始使用时，“此前已花”作为可见、可编辑的预算调整项，记录覆盖截止日期。之后导入该截止日期以内的账单时，不直接再扣预算：预览提示存在重叠，用户选择跳过重叠记录，或将调整项人工改为尚未被明细覆盖的金额后再导入。不得假定导入文件覆盖全部旧消费并自动清零。

## 5. 付款通知辅助记账

采用 Android NotificationListenerService，用户在系统设置主动开启通知使用权。只处理微信、支付宝来源，排除其他应用；对微信等来源也只处理有明确交易语义的内容，不把普通聊天中的金额当作支付。

来源包名只用于过滤，不能单独证明通知是交易。自动入账要求匹配已验证的交易通知模板、金额明确且方向确定。未验证模板、交易类型不明确、字段缺失或疑似重复时进入待确认；明显无关通知丢弃。初始未经过真机验证的模板只能生成候选记录。用户可关闭自动入账，仅生成待确认记录。

系统没有发出可读通知、隐藏金额、后台限制、权限失效等均可能漏记。本能力不读取微信或支付宝私有数据库、不登录支付账户、不索取支付密码，也不能获取完整历史账单。权限状态与可能失效情况在界面可见，配置说明根据小米真机情况验证后编写，不先宣称已经适配。

候选记录只保留识别所需字段和简短交易片段，不保存无关聊天或完整通知历史。解析在本地完成。通知权限缺失不得造成核心功能崩溃。

## 6. 账单文件导入与去重

第一版支持微信、支付宝导出的 CSV/XLSX 交易账单；具体表头通过格式检测识别，不仅依赖文件名。处理中文表头、表头前的说明行、常见 UTF-8/GB18030 CSV 编码、带引号或换行字段，以及 XLSX 日期/金额单元格。文件通过系统文件选择器授权读取，不申请整个手机存储访问权。压缩包、加密文件及未知格式明确提示先解压或选择受支持文件。

流程：选文件 → 解析 → 预览总数、成功/失败行、分类和重复候选 → 用户修正/选择 → 事务性入账 → 展示实际新增/跳过数。整批失败时不得留下部分已扣预算的记录。失败行说明行号与原因，不能静默丢弃。

优先按付款平台与交易唯一编号去重；同一订单的付款和退款通过事件类型区分。相同文件重复导入的相同行应稳定识别。通知通常缺少订单号，与导入账单或手动记录的近似匹配只标记待确认，不按金额和时间直接删除，以免误删真实的同额多笔消费。用户确认合并时保留单条账目并补充来源，不再次扣款。

自动分类采用本地可编辑商户关键词规则。低置信度归入其他并提示确认，不宣称分类必定准确。真实账单格式适配需要样本证据；开发用合成测试样本不算真实平台导入验证。

## 7. 数据结构与模块边界

- MonthBudget：月份、生活费、上月结转选择、此前已花调整、覆盖截止日期。
- Reservation：月份、名称、目标金额、是否作为下月模板。
- Transaction：稳定 ID、类型、金额分、日期与时间、分类、付款方式、商户、备注、预算收入标志、原交易/预留关联、来源与外部编号。
- ImportBatch / SourceEvent：导入或通知来源、去重标识、候选状态、解析错误及关联账目；仅保留必要信息。
- Category / ClassificationRule：内置及自定义分类、商户关键词与用户修正。

预算计算为独立纯逻辑模块；通知和文件解析只产生标准候选，统一由入账服务校验和写入，避免不同入口采用不同预算算法。Room 数据库事务保证账目和来源状态一致。UI 通过仓库观察数据变更，不另外持久化容易失真的汇总余额。

## 8. 本地保存与备份

账本保存在应用私有存储，核心使用离线完成，第一版不接入云同步、广告或分析 SDK。明确配置系统备份策略，避免默认把账本交给系统云备份。

手动导出带版本号的 JSON 备份，覆盖预算、账目、分类、预留及必要去重关联。导出前说明文件包含财务数据。恢复前校验结构、金额、枚举、引用和版本，并预览数据量；采用整体替换模式，必须用户确认，失败回滚不损坏现有账本。第一版不提供容易重复计账的跨备份合并。

卸载会删除应用内账本，设置中明确提示备份。备份是用户可选操作，不上传第三方服务。
