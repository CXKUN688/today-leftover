# 今日余粮 — 使用说明

「今日余粮」是一个完全离线的个人生活费账本。
它回答的问题不是「这个月花了多少」，而是**「照这样花下去，今天还能花多少」**。

> ### ⚠️ 先读这一条
>
> **「付款通知自动识别」实测不可用** —— 微信/支付宝通常不发出本应用能识别的付款通知，
> 因此**不会自动记账**。请使用**手动记一笔**或**账单导入**。详见第 7 节。
>
> 其余功能（预算、每日额度、预警、账单导入、备份）均正常可用。

## 1. 安装

### 方式一：ADB 安装（推荐）

```powershell
<工具链目录>\android-sdk\platform-tools\adb.exe install -r "deliverables\今日余粮-debug.apk"
```

### 方式二：手机直接安装

把 APK 传到手机上点击安装，需在系统中允许「安装未知来源应用」。

系统要求：**Android 9.0（API 28）及以上**。

安装前可校验文件完整性：

```powershell
Get-FileHash ".\今日余粮-debug.apk" -Algorithm SHA256
# 应为 9728f6ee6ea2911752d6635b695848a3772beb851884dae4a6dd513f863b9c12
```

## 2. 核心概念：两种「每天可花」

应用首页会同时显示两个金额，它们回答不同的问题，**不要混淆**：

| 名称 | 含义 | 何时变化 |
| --- | --- | --- |
| **剩余每天可花 · 含今天** | 可用余额 ÷ 本月剩余天数（含今天） | **每次记账后立即重算** |
| **今日额度剩余** | 今日参考额度 − 今天已用普通额度 | 随当天消费变化 |

- **剩余每天可花**是动态的：余额一变它就变。
- **今日额度剩余**基于「今日参考额度」，这个参考额度**每天只重建一次**，
  不会因为你多记一笔就重算，因此不会出现「下午首次打开应用，今天的额度被重复扣一遍」的问题。
- 当参考额度不足（今天已用超过参考额度）时会显示预警。

点击首页的「调整本月预算」可以修改本月生活费总额。

## 3. 日常记账

### 3.1 记一笔

点击右下角 **「记一笔」** 悬浮按钮：

1. 填写金额（单位：元，最多两位小数）
2. 选择类型：支出 / 收入 / 退款 / 内部转账
3. 选择分类与支付方式，可选填商家与备注
4. 点击「保存记录」

保存后首页的两个金额会同步更新。

### 3.2 四种账目类型的区别

| 类型 | 说明 | 是否计入本月支出 |
| --- | --- | --- |
| **支出** | 普通消费 | 是 |
| **收入** | 如生活费到账 | 否，增加可用余额 |
| **退款** | 关联到原消费的退款 | 否，冲抵原支出 |
| **内部转账** | 自己的两个账户之间转移 | 否，不改变余额 |

> **重要**：删除或调小一笔**已有部分退款**的原始消费会被明确拒绝。
> 必须先处理关联的退款记录，才能修改原消费——这是为了避免出现
> 「退款金额超过原支出」的不一致账本。

### 3.3 编辑与删除

在「首页」最近记录或「明细」页点击任意一条记录即可编辑或删除。

## 4. 预留资金

在「设置」页可以添加**预留**（如房租、学费等已确定用途的款项）。

预留的语义是：这笔钱已从生活费中划出，**不计入日常可花额度**。

- 预留款覆盖范围内的支出，**不占用普通日额度**
- 超出预留金额的部分，**计入普通日额度**
- 首页会分别显示「本月已支出」和「尚未使用的预留」

## 5. 消费预警

预警默认阈值为**三分之二**，可在「设置」页调整：

- 50%
- 三分之二（默认）
- 80%
- 关闭

规则：

- **每日每级最多提醒一次**，不会反复弹窗
- 预警等级：接近额度（NEAR）、已达额度（REACHED）、额度不足（INSUFFICIENT）
- 同级重复消费不会重复提醒；跨级会重新提醒

系统通知需要在「设置」页点击开启通知权限。
**权限被拒绝不影响记账**——账目照常保存，应用内仍会显示预警卡片。

## 6. 账单导入

目前支持**微信**和**支付宝**导出的 **CSV** 与 **XLSX** 账单。

### 6.1 操作步骤

1. 在微信/支付宝中导出账单（通常是压缩包，**请先解压**）
2. 进入「账单」页，点击导入按钮
3. 选择 CSV 或 XLSX 文件
4. **预览**解析结果，逐条确认
5. 确认无误后入账

### 6.2 导入规则

- **必须预览**：所有候选记录都需要你确认后才会入账，不会自动写入账本
- **自动去重**：同一账单文件重复导入不会重复记账
- **需确认的交易**：转账、红包、充值、还款、退款等类型会被标记为「需确认」
- **失败交易行**（如交易失败、已关闭）**不会**自动入账

### 6.3 实施防护上限

为避免超大或损坏文件导致卡死，设有以下硬性上限：

| 限制项 | 上限 |
| --- | --- |
| 账单 / 备份文件大小 | 20 MiB |
| XLSX 解压后总内容 | 100 MiB |
| XLSX 压缩包条目数 | 1000 |
| 最大行数 | 100,000 行 |

超过上限会**明确报错**并拒绝处理，不会覆盖或损坏已有账本。
如果你的账单超过 20 MiB，请**按月份拆分后再导入**。

### 6.4 已验证范围说明

- ✅ 微信 / 支付宝 **标准导出格式**的 CSV 与 XLSX（已通过合成样本测试）
- ⚠️ **真实平台账单尚未验证**——尚未用真实导出的账单文件测试过
- ❌ 不支持通用 Excel 引擎：只解析账单所需的 sharedStrings、inlineStr、数字与日期单元格，遇到未知结构会报错而非假成功

## 7. 付款自动识别 —— ❌ 实测不可用

> ### 请直接看结论
>
> **这个功能在真机测试中基本收不到微信/支付宝的付款通知，因此无法自动记账。**
> **请不要依赖它。记账请使用「手动记一笔」或「账单导入」。**
>
> 保留此功能与其开关，是因为代码仍在，未来可能改进；
> 但**当前版本对你没有实际用处**，不必去开启通知使用权。

### 7.1 为什么不可用

应用只能读取**系统通知栏**里出现的通知。但实际使用中：

- 微信/支付宝的付款结果**通常不以独立系统通知的形式出现**，
  尤其在应用内完成支付、或系统将通知折叠/静默时
- 即使出现通知，其标题与文本也**不包含**本应用识别所需的关键词（如「支付成功」）
- 部分系统版本对通知内容做了裁剪或延迟

结果是：监听服务**确实在运行**，但收不到可识别的通知，待处理列表始终为空。

已在小米 15（Android 17）上实测确认：授权通知使用权后正常付款，应用没有任何记录产生。

### 7.2 应用内如何提示

「账单」页顶部会显示明确的橙色警告：**「实测不可用，请勿依赖」**。
系统「通知使用权」列表里该服务的名称也标注为**实验性**。

### 7.3 如果你仍想尝试

仅供了解，**不推荐**：

1. 在「账单」页点击「开启通知使用权（可选）」
2. 在系统设置中授权「今日余粮付款通知识别（实验性，实测多不可用）」
3. 正常使用微信/支付宝付款，观察待处理列表是否出现记录

即使出现记录，它也**一律标记为「需确认」**，必须由你核对金额和类型后手动入账。

其他行为约定：

- 只处理**微信**（`com.tencent.mm`）和**支付宝**（`com.eg.android.AlipayGphone`）两个来源
- 普通聊天消息**不保存原文**，只保留必要的交易片段
- 缺少可识别金额的通知不会入账
- 同一个通知的多次更新不会重复扣款
- 「接收通知使用权」和「发送通知权限」是**两个独立权限**，
  且都**不影响**手动记账、账单导入、预警与备份等核心功能

## 8. 备份与恢复

### 8.1 导出

「设置」→ 导出备份，保存为版本化 JSON 文件。

> 备份文件**包含完整财务信息**，请妥善保管。

### 8.2 恢复

「设置」→ 恢复备份，选择之前导出的 JSON 文件。

恢复是**整体替换**：会覆盖当前全部账目、预算和设置。
应用会先弹出确认对话框，建议先导出当前账本作为备份。

安全保护：

- 损坏、版本未知、超限或引用断裂的备份会被**拒绝**，**旧账本保持不变**
- 恢复后**保留当日已提醒等级**，旧待投递事件**不会重新发送**，避免恢复后提醒轰炸

### 8.3 卸载风险

应用关闭了系统默认云备份（`android:allowBackup="false"`）。
**卸载应用会删除全部本地数据**，且无法从云端恢复。卸载前请务必先导出备份。
